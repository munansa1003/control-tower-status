# control-tower-status

개인 관제탑([control-tower](https://github.com/munansa1003/control-tower))의 **데이터 리포**다.
사람이 손으로 고치는 곳이 아니라, 매시간 도는 GitHub Actions 수집기가 결과를 커밋하는 곳이다.

| 파일 | 내용 |
|---|---|
| `status.json` | 관제 대상 프로젝트의 최근 커밋·CI·배포 상태 스냅샷. 대시보드가 이 파일을 읽는다. |
| `alert-state.json` | 경보 엔진의 전이 판정 상태. 다음 실행이 읽어 "무엇이 새로 나빠졌는지"를 가린다. |

## 왜 리포를 둘로 가르나

수집기는 private 리포 여러 개를 읽는 토큰을 쥔다. 그 토큰이 공개 리포 쪽 설정에 닿으면
사고 반경이 private 소스 전체가 된다. 그래서 읽기 토큰은 private 리포에 두고, 이 리포에는
**이 리포 하나만 쓸 수 있는** 쓰기 토큰만 온다. 그 토큰이 새도 반경은 "이미 공개인 파일을
고칠 수 있다"에서 끝난다.

여기에는 토큰도, 경보 토픽도, 개인 지표(CPU·세션 수)도 들어가지 않는다.

## 갱신이 멈추면

`status.json`의 `lastRunAt`이 두 주기(2시간)를 넘으면 대시보드가 stale 경고를 띄우고,
외부 데드맨(healthchecks.io)이 폰으로 알린다.
